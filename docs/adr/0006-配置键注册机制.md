# ADR-0006：配置键注册机制——register_config_key + 读取侧 validator，集中声明不物理分散

- **状态**：Accepted（2026-10-10，Wave 3 任务 2.2 落地）
- **日期**：2026-10-10
- **来源**：technical_roadmap Phase 2.2、architecture_review_report 建议
  「配置可扩展化」、`core/config.py` 头注释与 `register_config_key` docstring、
  `tests/contract_check.py` [6] 节

## 背景

路线图 Phase 2.2 的原始设想是：`DEFAULTS` 改为**启动时由各领域模块自注册**
（session/scheduler/cache/ui 各自注册自己的键）。落地前评估发现两个结构性
问题：

1. **导入环风险**：把注册语句物理搬进领域模块，config 要 import 领域模块
   才能收集键，而领域模块（session 等）本来就 import config
   （session.py:31 `from .config import lt_proxy_settings` 实证）——
   形成 config→领域→config 环；
2. **隐式时序耦合**：注册分散后，「键是否存在」取决于「该领域模块是否被
   import 过」。测试里单独 import config 就会看到缺键；启动路径不同 →
   DEFAULTS 键集不同——这类 bug 比集中声明难排查一个数量级。

同时既有 20 个 DEFAULTS 键是对外契约（安卓 SettingsStore 对齐同一键名/值域，
见 ARCHITECTURE.md §5），不能动。

## 决策

1. **提供 `register_config_key(key, default, validator=None)` 注册入口**
   （config.py:91）：新功能的键经此注册进 DEFAULTS，不改源码表；能推断
   bool/int/str 时同步登记 `_TYPES`（QSettings 读取类型）。
2. **既有键保持集中声明**：DEFAULTS 表按领域分组注释（网络/代理、缓存、
   UI、入站…），逐字冻结不动；表头注释写明「新增键请走 register_config_key，
   本表只留历史契约」。**未**把注册物理搬进领域模块——理由即背景两条，
   这是本 ADR 的核心权衡。
3. **validator 只在读取侧生效**（`AppConfig.get` → `_validate`）：非法值
   回落 default 并 log_warning，**绝不抛异常打断 UI**。写入侧不设卡——
   设置面板才能把「编辑框里尚未定型的中间值」照常落盘。无 validator 的
   既有键行为零变化（透传）。
4. **重复注册同键：拒绝，首注册者胜**（log_warning 留痕，DEFAULTS 原值不变）。
   若允许覆盖，DEFAULTS 取值将取决于领域模块 import 顺序（隐式时序耦合），
   同一键在不同启动路径下默认值不同——比报错更难排查；拒绝让冲突在注册点
   显性暴露。参数误用（空键名/validator 不可调用）直接抛 ValueError/TypeError
   ——编程错误必须在注册点炸。
5. **同一纪律推广到主题表**：ui.theme 的 `register_theme(name, palette)`
   同样「首注册者胜 + 非法入参注册点抛错」（ui/theme.py:96-118 实证），
   两处的防「生效值取决于注册顺序」是同一设计动机。

## 后果

- **正面**：新功能加键不再改 config.py 源码表（路线图可扩展性目标）；
  校验层可选、既有键零行为变化；冲突在注册点显性暴露。
- **负面 / 代价**：
  - 「各领域模块自注册」的路线图原文**没有完全兑现**——键的声明位置仍集中
    在 DEFAULTS 表（分组注释替代物理分散），这是本 ADR 有意偏离路线图原文
    的决定；roadmap 验收口径相应调整为「注册入口存在 + 新键可注册 +
    非法值被拒」。
  - validator 是注册方注入的回调，异常类型不可枚举——`_validate` 对
    validator 自身异常做宽泛兜底（config.py:131，注释说明为何宽泛），
    按非法处理回落 default。
- **门禁**：contract_check [6] 用临时键验证全链路（注册→get 回落 default→
  合法值放行→非法值回落→重复注册拒绝→空键名抛错→无 validator 键透传），
  测后即删不污染注册表。
